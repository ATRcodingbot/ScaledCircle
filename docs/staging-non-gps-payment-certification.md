# Staging non-GPS payment certification

`StagingNonGpsPaymentCertificationV1` is a single private, non-field TEST task.
It does not change ordinary canvassing, native GPS, completion thresholds or
production paid-work access. Runtime requires the staging project, `APP_ENV=staging`,
the dedicated enable flag, `LIVE_PAID_WORK_ACTIVATION_ENABLED=false`, and four
distinct server-configured actor bindings. Only a TEST Stripe secret is packaged.
Actor identifiers and operational evidence stay outside the repository.

The authenticated Admin creates the immutable task. The intended Business owner
prepares one TEST Checkout: $5.00 fixed compensation, no bonus, $1.00 platform fee,
$6.00 total. No location is requested or inferred. The existing signed campaign
funding webhook must reconcile payment, and subsequent work transitions verify
the TEST PaymentIntent and charge independently. A browser return is not proof.

The intended verified Scaler applies, the Business assigns, and the Scaler accepts
the fixed contract. The Scaler performs the platform checks and submits written
observations. The Business reviews those observations and explicitly approves
$5.00 TEST compensation. No administrator can submit or approve in their place.
No ordinary open opportunity or broad notification is created. The task cannot
enter `open` discovery. Its private projection is owner/assignee scoped, while
older staging clients can continue their ordinary `status=open` queries.

No campaign zone exists before submission. Its first state is `submitted`, which
cannot start the maintained tracking workflow. No route, GPS point, location
permission, photo, coverage percentage or physical work evidence is invented.
The submission is explicitly labeled `authenticated_task_attestation`. A completed
record carries that evidence type and the dedicated authority version.

Approval invokes the existing atomic TEST reserve-settlement authority. It records
one $5.00 earning, one matching Scaler Wallet credit and $1.00 recognized platform
fee. The existing referral reconciler can then record a separate $0.05 platform
liability. It cannot deduct worker pay or create a Business surcharge. The reward
remains held under the manual launch policy; this path never releases or pays it.
It never executes a Scaler cash-out or claims a bank payout was certified.

The staging source-reward adapter runs before the payable-liability mirror. This
shares the existing earned notification with asynchronous settlement triggers,
so delayed delivery or approval retries do not announce the same reward twice.
The source reward is provenance for the single liability; the referral portal
uses the liability ledger without adding the source record to its balance.

Task creation, work transitions, settlement and referral reconciliation are
idempotent. Checkout retries reuse the exact immutable parameters and key;
unknown outcomes outside the bounded recovery window require review instead of
a replacement session. Approval retries recover referral reconciliation without
posting another earning. Provider refunds/disputes and changed contracts block
new work transitions.

The dedicated entry is generated by
`functions/scripts/prepare_staging_payment_certification.js`. Deploy only its
single selector using `firebase.staging-payment-certification.json` with an
explicit staging project. Do not use the shared Functions inventory. This
manifest is absent from production promotion manifests.

The staging page is `/staging/payment-certification`, also reachable from staging
Admin. Current account/role, approval and required consent are checked on the
server for every action. The page is unavailable in production.

Local emulator tests are software evidence only. Hosted TEST payment, the actual
Scaler's observations and the Business's review must occur through their real
authenticated sessions before hosted referral economics can be called certified.
Account closure, email reuse and LIVE payout certification remain separate gates.
